# RuTube для PipePipe

<img src="docs/logo.png" width="96" alt="RuTube plugin logo">

Плагин добавляет сервис **RuTube** ([rutube.ru](https://rutube.ru)) в
[PipePipe](https://github.com/InfinityLoop1308/PipePipe): видео, прямые эфиры, Shorts,
каналы с разделами, плейлисты, поиск, комментарии, «В трендах» и «Телеканалы».

> **Плагин написан нейросетью.** Код, отладка и релизы сделаны AI-агентом (Arena.ai)
> по заданию владельца репозитория. Продуктовые решения и приёмка — на человеке.

## Статус

* Версия **1.0.4** (`versionCode 5`), пакет [`release/rutube-5.ppp`](release/rutube-5.ppp).
* Плагин можно поставить файлом или подключить этот репозиторий по URL — см. «Установка».
* В общий каталог [`awesome-pipepipe-plugins`](https://github.com/InfinityLoop1308/awesome-pipepipe-plugins)
  **пока не отправлен**: PR не открыт, поэтому в приложении его там нет. После мержа
  плагин появится у всех, кто добавил этот каталог в настройках.
* В основном репозитории PipePipe его нет: сторонние сервисы подключаются только
  плагинами.

## Установка

**Файлом**

1. Скачать [`release/rutube-5.ppp`](release/rutube-5.ppp) на телефон.
2. PipePipe → Настройки → Плагины → установка из файла, выбрать `.ppp`.
3. Перезапустить приложение.

Обновления ставятся поверх: ключ подписи не менялся с 1.0.1. Только версию 1.0.0 (старый
ключ) нужно удалить перед установкой.

**Репозиторием**

Настройки → Плагины → Add repository, вставить:

```
https://raw.githubusercontent.com/ivan23456-super/rutube-plugin/main/release/index.json
```

## Что умеет

| Возможность | Источник данных |
|---|---|
| Воспроизведение | `GET /api/video/{id}/`, `GET /api/play/options/{id}/` → HLS |
| Прямые эфиры | `live_streams` и `video_balancer` из play options |
| Субтитры | `captions` из play options (SRT/VTT) |
| Каналы | `GET /api/profile/user/{id}/` + `GET /api/video/person/{id}/` |
| Разделы канала | «Видео» (`origin__type=rtb,ifrm,rspa`), «Shorts» (`rshorts`), «Прямые эфиры» (`rst`), «Плейлисты» (`GET /api/playlist/user/{id}/`) |
| Слаги каналов | `/u/{slug}/` — id достаётся из состояния серверной страницы |
| Плейлисты и фильмы | `GET /api/playlist/custom/{id}/`, `GET /api/metainfo/tv/{id}/`, видео — `/api/playlist/custom/{id}/videos/` |
| Поиск | видео — `/pangolin/api/web/v1/search/combined/video_playlist`, каналы — `/api/search/combined/cards/list`, Shorts — `/api/search/shorts`; фильтры по дате и длительности |
| Подсказки | `GET /api/search/suggest` |
| Комментарии | `GET /api/v3/comments/video/{id}/` |
| «В трендах» | `GET /api/v2/video/recommendation/main` |
| «Телеканалы» | `GET /api/v2/video/stream/tvbroadcastinfo?alias=all&category=1` — эфиры с `rutube.ru/feeds/live/` |
| Приватные видео | токен `p` из ссылки пробрасывается в API |

Логин для всего перечисленного не нужен: используются публичные эндпоинты RuTube.

### Ограничения

* **Сортировки в поиске нет** — бэкенд RuTube её не поддерживает.
* **Поиска по плейлистам нет** — RuTube такие результаты не отдаёт.
* **Платные эфиры** (подписки «Спорт», «Всё включено», PREMIER и т. п.) анонимно не играют:
  RuTube отдаёт заглушку `subscription: <код>`. Плагин показывает её человеческим текстом,
  но поток не получает.
* **Вход в аккаунт** в настройках плагина объявлен как cookie-логин и в реальности не
  проверялся: веб-плеер RuTube авторизуется токеном, а не cookies, поэтому рассчитывать
  на него не стоит.
* **Телеканалы гео-заблокированы**: вне России RuTube отвечает заглушкой `blocking_rule`.
  Текст ошибки показывает, что именно вернул сервер.

## История версий

**1.0.4** — иконка плагина приведена к требованиям PipePipe: белая «R» на прозрачном
фоне (приложение тинтует её в цвет темы). Цветной логотип лежит в `docs/logo.png` и
используется только здесь. В описание добавлена пометка про нейросеть.

**1.0.3** — «Прямые эфиры» больше не показывают завершённые трансляции: RuTube держит у них
`is_livestream: true`, а настоящий признак — `is_on_air`. Завершённый эфир по прямой ссылке
даёт понятное сообщение вместо `stream_access_fail`; сохранённая запись (`duration > 0`)
играется как обычное видео. Названия подписок в ошибках показываются и для кодов (`SPORT`),
и для готовых имён (`Подписка PREMIER`).

**1.0.2** — у канала появились все разделы: «Видео», «Shorts», «Прямые эфиры» и
«Плейлисты» (с открытием плейлистов). Добавлен раздел «Телеканалы» — все прямые эфиры
с `/feeds/live/` с постраничной подгрузкой. Ошибки по подписке, 18+ и гео-блокировке
переписаны человеческим текстом.

**1.0.1** — заработали «В трендах» и фильтры поиска (по дате и длительности), починены
прямые эфиры (заголовки веб-плеера, поиск HLS в разных форматах play options), добавлена
пагинация Shorts по HTTPS, заглушки RuTube превращаются в понятные ошибки.

**1.0.0** — первая сборка для личного теста; её ключ подписи утерян, поэтому обновляться
с неё нельзя — только удалить и поставить 1.0.1 или новее.

## Сборка

Нужны JDK 25 (Gradle скачает тулчейн сам) и Android SDK с `build-tools;37.0.0` и
`platforms;android-36`; путь к SDK — в `local.properties` (`sdk.dir=...`) или в `ANDROID_HOME`.

```bash
./gradlew :tools:genKey   # один раз: создаёт signing.key в корне (в git не попадает)
./gradlew :tools:index    # собирает .ppp и подписывает: build/repo/*.ppp + build/repo/index.json
```

`assembleRepo` (сборка `.ppp`) вызывается как зависимость `:tools:index`, отдельно его
запускать не нужно. Другой ключ можно указать через `-PpluginSigningKey=/path/to/key`.

Релиз вручную: скопировать `build/repo/rutube-<versionCode>.ppp` в `release/`, обновить
`release/index.json` (абсолютный URL в `package`, плюс `sha256`, `signature`, `publicKey`,
версия) и закоммитить. `versionCode` в `src/main/resources/plugin.json` поднимается
каждым релизом.

GitHub Actions:

* `.github/workflows/ci.yml` — на PR и на пуши в ветки: собирает и подписывает одноразовым
  ключом, только чтобы проверить, что всё компилируется и пакет валиден.
* `.github/workflows/build.yml` — на изменения в `src/**`. Если заведён секрет
  `PLUGIN_SIGNING_KEY`, workflow подписывает пакет настоящим ключом и коммитит `release/`.
  Секрет сейчас не заведён, поэтому сборка идёт без подписи: по маркер-файлу
  `REQUEST_PACKAGE` она кладёт пакет в `ci-artifacts/`, а подпись ставится вручную тем же
  ключом перед коммитом в `release/`.

## Ключ подписи

Ed25519. Публичный ключ прикрепляется при первой установке (pinning):

```
DLCC7suGGj0xX5WwB/zTTjCFs+3JJV8jWaBWGKb52es=
```

Приватный ключ (base64 raw Ed25519, 44 символа) хранится только у владельца репозитория и
в git не попадает. Обновления принимаются только с этим ключом и этим `pluginId`: если
ключ потерян, плагин придётся выпускать под новым `pluginId`, а пользователям —
переустанавливать его вручную.

Если положить ключ в GitHub-секрет `PLUGIN_SIGNING_KEY`, `build.yml` будет подписывать
релизы сам.

## Структура

```
src/main/java/org/pipepipe/rutube/   сервис, хелперы, экстракторы, link-хендлеры, фильтры
src/main/resources/plugin.json       манифест (name = имя сервиса)
src/main/resources/icon.png          иконка плагина: белая «R» на прозрачном (тинтуется приложением)
docs/logo.png                        цветной логотип для README
docs/pipepipe-plugins-guide.md       конспект по устройству плагинов PipePipe
tools/                               genKey + index (BouncyCastle, nanojson)
release/                             подписанный .ppp и index.json
.github/workflows/                   ci.yml (проверка), build.yml (сборка и релиз)
```
